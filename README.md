# SliceQ · 直播切片工作台

[**English**](README.en.md) | 中文

> 把一场几小时的直播录像，自动找出高光、切好、配上字幕，导出成可直接发布的内容，
> 以及能继续精修的时间线（剪映草稿 / 达芬奇 OTIO）。

基于多模态大模型（Qwen-Omni 系列）· Windows 桌面应用 · MIT 开源 · **自带 API Key（BYOK）**

**当前版本**：`v0.1.0`（阶段 0~5 完成，功能可用）

> ⚠️ **使用前请读[免责声明](#免责声明)**：请只处理你有权处理的素材，
> 切片内容的版权与平台合规责任由使用者自负。

---

## 它解决什么问题

一场 3 小时直播里真正能用的可能只有十几分钟。完整看完一遍要 3 小时，
而找出来之后还要切片、配字幕、导入剪辑软件 —— 一共大半天。

SliceQ 做的是**前半段全部自动化**：

```
录播文件 → 转录 → 找出高光 → 切片+字幕 → 成片 / 时间线草稿
         (本地免费)  (多模态分析)  (FFmpeg)    (继续精修)
```

**它不替代剪辑软件。** 它负责把你送到"精修起点"，最后还是你在剪映/达芬奇里收尾。

## 功能

| 模块 | 能力 |
|---|---|
| **导入** | 本地视频文件拖放；B 站等 URL 链接（yt-dlp） |
| **转录** | FFmpeg 内置 whisper，**全本地跑、零 API 成本**；自动清理幻觉重复 |
| **粗筛** | 按你的需求描述，用文本信号把几小时压到几十个候选窗口 |
| **精析** | 多模态模型直接看画面+听声音，判高光、给理由、给标题 |
| **成本可见** | 开始前给预估上限 → 粗筛后给你唯一确认点 → 事后对账 |
| **切片** | 按候选切成独立 MP4，可选淡入淡出、BGM 自动闪避人声、自动选封面 |
| **字幕** | ASS 样式系统（字体/配色/描边/双语对照），同时产出 SRT |
| **文案** | 为每条切片生成标题与简介文案 |
| **批量** | 多条候选并发处理；多个录像排队串行 |
| **导出** | 剪映草稿 / 达芬奇 OTIO / 降级包（三通道） |

## 快速开始

### 方式一：下载即用（推荐）

1. 到 [Releases](https://github.com/cunnak/SliceQ/releases) 下载 `SliceQ.exe`
2. 双击运行。**不需要安装 Python**
3. 首次启动会引导你完成三件事（见下节）

> Windows 可能会提示"未知发布者"——这是未做代码签名的正常现象，
> 点"更多信息 → 仍要运行"即可。

### 方式二：从源码运行（开发者）

```bash
pip install -r requirements.txt
python -m sliceq
```

要求 Python ≥ 3.11（开发用 3.13）。

## 首次启动要准备的三件事

| # | 事项 | 说明 |
|---|---|---|
| 1 | **百炼 API Key** | 分析高光要用多模态模型，见[下文](#获取百炼-api-key) |
| 2 | **FFmpeg** | 设置页会检测。缺失或版本不含 whisper 滤镜时，点「自动下载安装」（约 180MB） |
| 3 | **whisper 模型** | 选一档下载（推荐 `large-v3-turbo`，约 1.6GB）。走国内镜像 |

> ⚠️ **首次启动需要下载约 1.8GB**（FFmpeg + 模型），请留出时间与磁盘。
> 这些**都不打包在 exe 里**（原因见[第三方组件](#第三方组件与许可)），
> 下载后存在 `%APPDATA%\SliceQ\`，只下一次。
>
> 转录是**纯本地**的：装好之后，切多少视频都不额外花钱。

## 获取百炼 API Key

1. 打开 [阿里云百炼控制台](https://bailian.console.aliyun.com/)，用支付宝/淘宝账号登录
2. 首次进入按提示**开通模型服务**（个人使用有免费额度）
3. 在**模型广场**确认可用模型中有 `qwen3.8-omni-flash`（本版本使用该模型）
4. 右上角头像 → **API-KEY** → 「创建我的 API-KEY」→ 复制
5. 回到 SliceQ → **设置** → 粘贴到 API Key 输入框 → 保存

> 🔒 Key 用 **Windows DPAPI 加密**后存在本机（`%APPDATA%\SliceQ\credentials.bin`），
> 只绑定当前 Windows 用户，**换机器无法解密**。
> Key 只会发往你配置的端点，程序不含任何回传。

## 成本

**转录免费**（本地 whisper），花钱的只有"精析"这一步。

| 项 | 量级 |
|---|---|
| 单条候选精析 | 约 **¥0.5** 上下（实测校准，随素材与时长浮动） |
| 3 小时直播全流程 | 远低于同类按分钟计费的服务 |
| 切片/字幕/导出 | **¥0**（纯本地 FFmpeg） |

程序会在开始前给出预估上限，并在粗筛完成后**停下来等你确认**——
你可以在看到候选数量和预估花费后再决定要不要继续。

> 想省钱：把「筛选强度」调低，粗筛会留下更少窗口进入精析。

## 导出通道

导出对话框可勾选三项，互不冲突：

| 通道 | 产出 | 后续 |
|---|---|---|
| **成片片段** | 每条候选一个 MP4（+ SRT） | 直接发布 |
| **剪映草稿** | 视频轨 + 字幕轨 + 标题轨 | 在剪映里继续精修 |
| **达芬奇时间线** | `.otio` + 并行 `.srt` + `导入说明.txt` | 在达芬奇里继续精修 |

### ⚠️ 剪映：成片需要在剪映里手动导出

SliceQ 只把**草稿**写进剪映的草稿目录。
剪映 7 之后已经无法由外部程序触发导出，**最后一步渲染请你在剪映里点**。

### ⚠️ 达芬奇：两条必须知道的注意事项

导出包里带了一份 **`导入说明.txt`**，请照着做。其中最关键的两条：

1. **首次导入会弹「找不到片段」——这是正常的。**
   `.otio` 格式只记录切点、不携带视频本身。选【是】并指向素材文件夹即可。

2. **导入字幕要用「按时间码插入」，不要直接把 `.srt` 拖进时间线。**
   实测：拖拽会让达芬奇从时间线第 0 帧开始排列，**丢掉第一条字幕的起始偏移**，
   导致全部字幕整体提前约 0.5 秒（不报错，但看得出来）。

### 字幕样式不跟随导出（刻意如此）

你在 SliceQ 里设的字幕样式**不会**带进导出通道：
剪映用自己的默认样式；达芬奇用并行 SRT，样式在达芬奇里自行设置。
这是两套样式体系差异过大导致的取舍，已在导出对话框、结果文本、`导入说明.txt` 三处明说。

## 数据存放位置

全部在 `%APPDATA%\SliceQ\`：

```
SliceQ/
├── db/sliceq.db          任务、片段、字幕、标记
├── credentials.bin       API Key（DPAPI 加密）
├── settings.json         偏好设置
├── logs/sliceq.log       运行日志（滚动，出问题时请看这个）
├── bin/                  自动下载的 FFmpeg
├── models/               whisper 模型
├── downloads/            URL 导入的源视频
├── styles/               字幕样式预设
├── bgm/                  背景音乐（需自备，见目录内说明）
└── export/               默认导出目录
```

**卸载 = 删掉这个目录**（程序本身是绿色的单文件）。

## 常见问题

**Q：提示「没有找到候选段」，我该改什么？**
先看日志（`%APPDATA%\SliceQ\logs\sliceq.log`）。这个提示有**不同病因**：
API Key 无效、额度不足、端点不通、或素材内容被模型的安全审核拦截。
程序会尽量把原始原因带出来，但请以日志为准。

**Q：转录质量不好怎么办？**
换更大的 whisper 模型（设置页）。`large-v3-turbo` 是质量/速度平衡点。
另外素材本身的音质影响很大 —— 有背景音乐或多人同时说话的段落本来就更难。

**Q：切出来的片段没有声音 / 时间线不对？**
请先确认用的是最新版本。达芬奇的时间线起始时间码与本素材帧率有关，
`导入说明.txt` 里有对应的处理步骤。

**Q：能不能不用 AI，只做转录和字幕？**
可以。转录与切片完全本地，不填 Key 也能用到字幕这一步（精析才会用到模型）。

## 第三方组件与许可

本项目以 **MIT** 许可开源。以下组件**不打包进 exe**，或在独立授权下使用：

| 组件 | 许可 | 使用方式 |
|---|---|---|
| **FFmpeg** | **GPL**（gyan.dev 构建） | **不打包**。由用户在首次使用时下载到自己的目录，程序通过 `subprocess` **以独立进程调用**——属 GPL FAQ 认可的"聚合"，不与 MIT 冲突 |
| **whisper 模型** | MIT（OpenAI） | 不打包，运行时下载 |
| `pyJianYingDraft` | Apache-2.0 | 作为库引用，用于生成剪映草稿 |
| `OpenTimelineIO` | Apache-2.0 | 作为库引用，用于生成 `.otio` |
| `PySide6-Essentials` | LGPL-3.0 | 作为库引用（Qt） |
| `yt-dlp` / `requests` / `Pillow` / `py7zr` | 各自开源许可 | 作为库引用 |

**字体**：本项目**不随包分发任何字体**，字幕渲染使用操作系统中已安装的字体。
若你导出成片时用了某款字体，请自行确认该字体的授权范围。

**背景音乐**：本项目**不内置任何 BGM**（音频版权无法像字体那样妥善随包分发），
`bgm` 目录留给你自行放入有授权的音乐。
