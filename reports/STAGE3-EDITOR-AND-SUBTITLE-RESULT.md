## 二、产品决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 导出产物形态 | **乙：每条候选一个独立 mp4** | 切片 man 要的是能单独发布的一条条短视频，不是一个几十分钟合集 |
| 切片流水线 | 两步走（切 → 烧），快速模式做等价捷径 | 进度反馈必需；`filter_complex` 一次成型是黑箱 |
| 字幕承载格式 | **ASS** | 主/副字幕要各自独立的字体、颜色、边框 —— SRT 做不到 |
| 快速/精确 | 两模式并存，默认精确 | 实测数据见下 |

**乙方案的技术红利**：时间轴重映射从「跨段累加」退化成「整体平移」——
`timeline_t = source_t - clip.start`。设计文档曾专门警告过跨段累加是
"不报错但结果全错"的高发区，乙方案直接消掉了这一整类风险。

## 三、关键实测结论（全部有可复跑证据）

### 3.1 ASS 双样式完全独立 ✅

同一帧里主/副字幕的**字体、字号、颜色、边框色、边框粗细、垂直位置**互不干扰。
颜色格式 `&HAABBGGRR`（**B 与 R 对调**）已验证往返一致。

### 3.2 Windows 路径必须双反斜杠转义 ⚠️

```
subtitles=C:/...      → 失败（Unable to parse "original_size"）
subtitles=C\:/...     → 失败（单反斜杠在第一层就被消费）
subtitles=C\\:/...    → 成功
```

**根治写法**：用相对路径 + `cwd`，路径里没有冒号就没有转义问题。
`subtitle_style.ass_filter_arg()` 优先走这条路。

### 3.3 中文字幕的自动换行不可靠 —— 必须自己做 🔴

libass 的 `WrapStyle` 对**中文**不可靠：中文没有空格，它把整串当一个不可断的
"词"，放不下时不是换行而是**溢出画布，超出部分直接裁掉**，且无任何警告。

实测：18 字字幕在 406px 宽、字号 42 的画面上渲染成
「维码过来叫我扫一下我付2」—— 首尾各少两个字。

⇒ 实现 `wrap_for_canvas()`：**先算需要几行，再按行数均匀分配**，
且每行都必须不超宽（均匀是"更好看"，不超宽是"不能丢字"，后者优先）。

### 3.4 `-ss` 前置时，ASS 的时间基准是「段内相对时间」✅

实测：切源 30~45s，ASS 里 0~3s 的字幕出现在输出第 1 秒的画面里，12 秒处无字幕。
⇒ `remap_to_clip()` 产出的时间可直接用，无需额外偏移。

### 3.5 两种切片模式的真实精度

| 模式 | 时长偏差 | 内容对齐 | 能否烧字幕 |
|---|---|---|---|
| 精确（重编码） | **0.000s** | PSNR 46.8（重编码损失） | ✅ |
| 快速（`-c copy`） | +0.10~0.15s | **PSNR = inf（逐像素完全一致）** | ❌ |

**设计文档里写的"快速模式 ±2s 误差"是错的**，实测小一个数量级。

### 3.6 字体缺失会静默 fallback ⚠️

给了不存在的字体名，渲染**照样成功**，只是换成默认字体。
用户看到的是"我改了字体但没反应" —— 必须在 UI 层校验并提示。

本机可用字体 390 个，其中中文字体 19 个。

### 3.7 `drawtext` 滤镜段错误 🔴（影响阶段 4）

```
Fontconfig error: Cannot load default config file
Segmentation fault
```

同一套字体依赖，`subtitles` 滤镜正常、`drawtext` 直接崩。
设计文档 §5 里"封面用 drawtext 加标题"**当前不可实现**，已登记为 R26。

## 四、本轮抓到的缺陷（**全部"不报错"**）

| # | 缺陷 | 症状 | 后果 |
|---|---|---|---|
| 1 | `run_ffmpeg` **没把 cwd 传给 subprocess** | `Unable to open xxx.ass` | 带字幕导出 100% 失败 |
| 2 | 用了 cwd 后**输出的相对路径基准变了** | `Error submitting a packet to the muxer` | 输出写到不存在的目录 |
| 3 | `Worker.run()` **只捕 `Exception`** | `SystemExit` 穿透 | **信号永不发出，UI 永远卡在"渲染中"** |
| 4 | `WorkerPool` **不持有运行中 worker 的引用** | **段错误（access violation）** | 进程直接崩，栈里看不到业务代码 |
| 5 | 重映射**丢弃计数漏算"完全在段外"** | 保留数 + 丢弃数 ≠ 输入数 | 报告里报出假数字 |
| 6 | 中文字幕**溢出被裁**（见 3.3） | 首尾各少两个字 | 内容缺失且无警告 |
| 7 | editor **让调用方猜视频尺寸** | ASS 的 PlayRes 与成片不符 | 字号/位置全走样 |
| 8 | 样式页**预设下拉未初始化** | 下拉是空的 | 用户看到"当前样式"一行什么都没有 |
| 9 | 断句**只单向合并短条** | 2 字碎片残留成一条字幕 | "饭"单独占一行 |

其中 3、4 是**通用健壮性缺陷**，影响所有走线程池的功能（不只本阶段）。

## 五、核心链路的设计取舍

### 5.1 时间轴重映射是"唯一实现"

`subtitle.remap_to_clip()` 是**唯一**的映射函数。
SRT 导出与字幕烧录都调它 —— 这正是 TECH-DESIGN §4.5 的硬要求
（各写一份的话，两者会随时间悄悄不一致，用户拿到的 SRT 和看到的画面对不上）。

### 5.2 边界处理：宁可没有，也不要显示半句

一句话跨越片段边界时看**落在段内的比例**：
- ≥ 55% → 保留，时间裁到边界
- < 55% → 丢弃（只露半句比不显示更糟）

### 5.3 烧字幕必须重编码 —— 但要说出来

用户同时选「快速」+「烧字幕」时，自动升到精确模式，
并**在对话框和导出清单里都写明**为什么。悄悄丢掉字幕是最坏的选择。

### 5.4 转录分段必须落库（schema v4）

导出要生成字幕，原料是转录分段。原先它只在 asr 的分片缓存文件里，
导出侧够不着 —— 要么重新转录整条素材（3 小时要 20 分钟），要么做不出字幕。

新增 `transcript_seg` 表，与 `subtitle` 表分工明确：

```
transcript_seg = 转录的原始输出（句级，源视频时间轴）
subtitle       = 切分/重映射后的成品字幕（成片时间轴）
```

混用会让"重映射"失去可核对的原点。

### 5.5 预览走完整渲染链路

用 ffmpeg + libass 渲染真帧，而不是自己画字。
自己画的话，换行位置、描边粗细、字间距都会有细微差别 ——
**预览好看、成片不一样**，是最让人恼火的一类问题。
