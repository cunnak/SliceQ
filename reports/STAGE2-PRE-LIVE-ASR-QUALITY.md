## 三、幻觉：依模型而变（small/base 约 1/3，large-v3-turbo 仅 8%）

### 3.1 实测到的幻觉内容

```
謝謝收看!                                    ← 出现 3 次
謝謝大家收看「小明星」的影片。                  ← 出现 2 次
( 無所謂的 中文字幕)
(字幕:J Chong)                               ← 出现 2 次
( 忘記了 請按旁邊的小鈴鐺 )
(字幕製作:貝爾)
謝謝收看 下次見
```

**24 段里有 7~8 段是幻觉——约三分之一。**

### 3.2 性质

这些是 whisper 在**无语音片段**（静音 / 纯 BGM / 环境音）上的典型故障：
它会套用训练数据里的高频模板文本（YouTube 式的"谢谢观看"、"订阅"、"字幕组署名"）。

### 3.3 后果

**不能把"转录出了文本"当成"这段有语音"的证据。**

若粗筛按"转录文本的语义密度"排序，幻觉文本会被当成真实内容参与评分 ——
把**没有语音的片段推成候选**，白烧精析的钱。

### 3.4 对策

**`vad_model`（静音检测）从"可选加速"升级为"必需的正确性要求"。**

TECH-DESIGN §2.1 提到 `vad_model` 时的理由是"加速跳过静音段"，
**现在要升级为"防止幻觉污染粗筛"**。

> ⚠️ 待办：`vad_model` 需要额外的 VAD 模型文件（如 `ggml-silero-v5.1.2.bin`），
> 需一并加入模型下载清单。**本次未实测 VAD 效果**，属阶段 2 必验项。

## 四、速度：GPU 是必需品 🔴

### 4.1 实测数据（60 秒音频）

| 模型 | 设备 | 耗时 | 实时率 | **推算 3 小时直播** | 判定 |
|------|------|------|--------|-------------------|------|
| base | **GPU** | 9.8s | 0.16× | **0.49h** | ✅ |
| base | CPU | 65.7s | 1.09× | **3.28h** | ❌ |
| small | **GPU** | 5.7s | 0.09× | **0.28h** | ✅ |
| small | CPU | 52.3s | 0.87× | **2.62h** | ❌ |
| tiny | CPU | 28.8s | 0.48× | 1.44h | ⚠️ |

**本机 GPU：NVIDIA GeForce RTX 4060 Laptop GPU，8188 MiB，驱动 610.62**

### 4.2 关键推论

**CPU 下本地转录不成立。** 转 3 小时直播要 2.6~3.3 小时 ——
比实时还慢，用户"转完天都亮了"，产品体验为零。

**GPU 下完全成立。** small 只要 **17 分钟**，base 约 **30 分钟**。

### 4.3 ⚠️ 这暴露了一个用户分层问题

产品前提"**本地免费转录**"**只对有独立显卡的用户成立**。

| 用户类型 | 本地转录可行性 |
|---|---|
| 有独显（如 RTX 4060） | ✅ 17~30 分钟 |
| 仅核显 / 无独显 | ❌ 2.6~3.3 小时，不可用 |

**切片 man 大多有独显**（要剪视频），**但不是全部**。
对无独显用户必须有降级路径，否则产品对他们等于不可用。

候选降级方案（**待决策，见拷问分支 ②**）：
1. 启动时检测 GPU，无独显则明确警告"转录会很慢"
2. 无独显时引导改用云端转录（要花钱，需明示）
3. 无独显时自动降档到 tiny（牺牲质量换速度）——**但 tiny 质量不可用，等于没救**

### 4.4 测量说明（诚实标注）

⚠️ **base-GPU 的 9.8s 偏大**，因为它是**第一个跑的 GPU 任务**，含一次 CUDA 上下文初始化开销；
small-GPU 的 5.7s 是热态。**所以 base/small 的 GPU 速度不能直接横比**，
但两者都远低于 1.0× 实时，结论（"GPU 可用、CPU 不可用"）不受影响。

## 五、large-v3-turbo 实测（用户指定为默认后的验证）

### 5.1 两个版本的体积

| 文件 | 体积 |
|---|---|
| `ggml-large-v3-turbo.bin`（完整） | **1,549 MB** |
| `ggml-large-v3-turbo-q5_0.bin`（量化） | **547 MB** |

### 5.2 速度实测（60 秒音频）

| 模型 | 设备 | 耗时 | 实时率 | 3 小时直播 | 判定 |
|------|------|------|--------|-----------|------|
| small | GPU | 5.9s | 0.10× | 0.29h | ✅ |
| **large-v3-turbo（完整）** | **GPU** | **7.5s** | **0.13×** | **0.38h** | ✅ |
| large-v3-turbo-q5_0 | GPU | 17.5s | 0.29× | 0.87h | ⚠️ |
| large-v3-turbo（完整） | CPU | 131.5s | 2.19× | 6.57h | ❌ |
| large-v3-turbo-q5_0 | CPU | 164.0s | 2.73× | 8.20h | ❌ |

### 5.3 ⚠️ 反直觉发现：量化版反而更慢

**`q5_0`（547MB）比完整版（1549MB）慢一倍多**（0.29× vs 0.13×）。

**推测原因**：whisper.cpp 的 ggml 后端对 `q5_0` 这个量化类型**缺少优化内核**，
反量化（dequantize）开销吃掉了参数变少带来的收益。

**⇒ 结论：量化版在这个场景下没有价值。** 体积小 1GB，但慢一倍。
**默认用完整版**（用户已指定），量化版保留在选项里但不推荐。

> ⚠️ 这是**单次测量**，且 GPU 上下文状态未严格控制（q5_0 前面刚跑完 small 的 CPU 任务）。
> 若要下定论需重复测量。**但差异幅度（2.2×）远超测量噪声，方向可信。**

### 5.4 GPU / CPU 输出差异（非确定性）

同一模型、同一音频，GPU 与 CPU 的输出**可能不同**：

```
large-v3-turbo GPU: ...谢谢观看好,我先把你放在一起可以有本事
large-v3-turbo CPU: ...谢谢观看好可以有本事了合你油了谢谢大家
```

**⇒ whisper 的推理不是确定性的**（涉及温度回退与束搜索）。
⇒ 不要把"两次结果不同"当成 bug；但也意味着**不能靠 diff 输出判断模型是否正常工作**。

### 5.5 质量观察（60 秒真实直播节选）

| 模型 | 关键句输出 |
|---|---|
| small | `...这种样子 或者这种烧饼手段全都要學會了...` |
| turbo-q5_0 | `...这种样子或这种骚逼你手段全他媽都學會了...` |
| turbo-full | `...这种TM这种样子或这种骚逼你手段全他媽都學會了...` |

**两者都有幻觉**（`谢谢观看`、`谢谢大家` 在三个模型的输出里都出现）。
**⇒ 换更大的模型并不能消除幻觉，VAD 仍然必需。**

## 六、VAD 实测：效果比预期弱得多（推翻了我先前的判断）

### 7.1 背景

此前（§3）基于 **small/base** 的输出，判断"约 1/3 分段是幻觉"，
因而主张 **VAD 是必需的正确性要求**。

用 large-v3-turbo + 精确的幻觉特征词统计重测后，**这个判断需要修正。**

### 7.2 VAD 模型的位置（找模型容易找错）

**VAD 模型不在 `ggerganov/whisper.cpp` 仓库里**，而在独立仓库 `ggml-org/whisper-vad`：

```
https://huggingface.co/ggml-org/whisper-vad/resolve/main/ggml-silero-v6.2.0.bin   (864 KB)
https://huggingface.co/ggml-org/whisper-vad/resolve/main/ggml-silero-v5.1.2.bin   (864 KB)
```

用法（filter 参数）：

```
vad_model=<路径>:vad_threshold=0.5
```

### 7.3 实测结果（60s 真实直播，large-v3-turbo，GPU）

| 配置 | 段数 | 疑似幻觉段 | 幻觉率 | 耗时 |
|------|------|-----------|--------|------|
| **不用 VAD** | 24 | **2** | **8%** | **7.6s** |
| VAD v6.2.0 @0.5 | 27 | **1** | **3%** | 23.9s |
| VAD v6.2.0 @0.6 | 27 | 5 | 18% | 22.1s |
| VAD v5.1.2 @0.5 | 27 | 5 | 18% | 22.1s |

（幻觉判定：匹配 `谢谢观看/謝謝收看/字幕:/小铃铛/…` 等特征词）

### 7.4 三条结论

**① large-v3-turbo 的幻觉本来就很少（8%），远低于 small/base 的约 33%。**
⇒ 换更大的模型确实抑制了幻觉。**之前"所有模型都一样幻觉"的说法不准确。**

**② VAD 的收益微弱且不稳定。**
最好情况 8% → 3%，**但阈值从 0.5 提到 0.6 反而恶化到 18%。**
⇒ **VAD 不是"越严格越好"**，阈值需要调，且最佳值依赖内容。

**③ VAD 让耗时增加约 3 倍**（7.6s → 22~24s）。
换算到 3 小时直播：**23 分钟 → 70 分钟**。

### 7.5 更根本的问题：本样本的幻觉，VAD 管不了

对照静音扫描结果：

```
全长 8959s 中，静音（≥1s，-35dB）仅 8 段、共 251.6s —— 占 2.8%
```

**那 2 段幻觉出现在 20.6s 与 32.4s —— 而全片第一段静音在 135.9s。**

⇒ **幻觉发生在有语音的区域。而 VAD 只能切非语音，原理上就管不了它们。**

### 7.6 修正后的判断

| 原判断 | 修正后 |
|--------|--------|
| 幻觉约 1/3，VAD 必需 | **幻觉率依模型与内容而变**：small/base ~33%，**large-v3-turbo 仅 8%** |
| VAD 是必需的正确性要求 | **VAD 收益微弱（8%→3%）且代价 3 倍耗时** |
| 静音检测能防幻觉 | **只能防"静音处的幻觉"，防不了"语音处的幻觉"** |

**⇒ 建议：VAD 做成可选开关，默认关闭。**
理由：3 倍耗时换 5 个百分点的收益（且不稳定），对"连续讲话"型内容不划算。

**⇒ 遗留待验**：本样本语音密集（静音仅 2.8%），
**无法反映"有 BGM / 长时间静音"的内容**。若真实用户素材中有大量这类内容，
VAD 的价值会显著上升。**需要在有 BGM 的素材上补测。**

### 7.7 另一个更划算的替代方案（未实现）

若目标只是"跳过静音"，**用 ffmpeg 的 `silencedetect` 比 whisper 的 VAD 便宜得多**：

```
实测：扫描 2.5 小时全长仅耗时 10 秒
```

思路：先用 `silencedetect` 找出静音区间 → 把音频切成"只含语音"的片段 → 只对这些片段转录。
**成本几乎为零，且能省掉静音的转录时间。** 列为阶段 2 的可选优化。

## 七、GPU 不降质 ✅

同一模型、同一音频，GPU 与 CPU 的输出**内容一致**：

```
base  GPU: 很牛皮啊,这些人很,他把牛皮呀我上次去店里面吃饭麻了累了要死餓了要死...
base  CPU: 很牛皮啊,这些人很,他把牛皮呀我上次去店里面吃饭麻了累了要死餓了要死...
```

差异仅在**空白字符与分段边界**（GPU 226 字 / CPU 234 字，内容相同）。

**⇒ 可以放心把 `use_gpu` 默认设为 `true`。**

## 八、其他发现

### 6.1 输出混有繁体

```
謝謝收看! / 媽的雷子要死 / 別的沒交動喔
```

即使是简体中文的直播，whisper 也可能输出**繁体字**。
⇒ 后处理需要**繁转简**（可用 `opencc` 或轻量映射表）。

### 6.2 相邻分段重叠

```
[14.7s → 44.7s]  ...      ← end 异常长（30 秒）
[17.7s → 19.7s]  ...      ← 下一段 start 落在上一段范围内
```

**分段首尾不相接，甚至出现包含关系。** 下游时间轴运算必须按"独立区间"处理，
不能假设 `prev.end == next.start`。

### 6.3 模型文件体积与实际下载速度

| 模型 | 体积 | 下载耗时 | 速度 |
|---|---|---|---|
| ggml-tiny | 74 MB | 15s | 4.9 MB/s |
| ggml-base | 141 MB | 6s | 23 MB/s |
| ggml-small | 465 MB | 8s | 58 MB/s |

hf-mirror 速度波动较大，但整体很快（**秒级**）。
