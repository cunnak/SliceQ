## 一、要解决的问题

上一轮实测发现 whisper 在**无语音片段上产生幻觉**：

```
請不吝點贊 訂閱 轉發 打賞支持明鏡與點點欄目
謝謝收看！／謝謝大家收看「小明星」的影片。／(字幕:J Chong)
```

这些不是真实内容，但**语意通顺**——粗筛若按语义密度打分，会把它们当成真实文本参与排序，
把没语音的片段推成候选，**白烧精析的钱**。

上一轮的结论是"VAD 是必需的"。**这一轮把它推翻了。**

---

## 二、结论摘要

| # | 结论 | 强度 |
|---|---|---|
| 1 | **ffmpeg whisper 滤镜的 `vad_model` 无法消除静音幻觉** | **已证**（源码 + 实测） |
| 2 | 它反而使耗时增加约 4 倍（12s → 46~48s / 140s 音频） | 已测 |
| 3 | **静音预切除有效**：幻觉 23 → 6（-74%） | 已测 |
| 4 | 叠加"重复文本剔除 + 特征词剔除"后：**23 → 0** | 已测 |
| 5 | 时间轴映射（拼接后 → 原轴）验证正确 | 已测 |

**对实现的要求**：`vad_model` **不采用**；改用"静音预切除 + 三层过滤"。

## 三、VAD 为什么无效（证据链）

### 3.1 先排除"参数没生效"

怀疑合理——参数名写错会被 ffmpeg 静默忽略。用**故意传非法模型**来鉴别：

| 用例 | 结果 |
|---|---|
| `vad_model` ← 不存在的路径 | 报错 `failed to open VAD model` |
| `vad_model` ← 音频文件 | 报错 `invalid model data (bad magic)` |

**参数确实被解析并加载了。** 排除这一可能。

### 3.2 源码给出的答案

`libavfilter/af_whisper.c` 的 `filter_frame()`：

```c
if (wctx->ctx_vad && (audio_buffer_fill_size - audio_buffer_vad_size) >=
                     av_rescale(vad_min_speech_duration + vad_min_silence_duration, ...)) {
    struct whisper_vad_segments *segments =
        whisper_vad_segments_from_samples(wctx->ctx_vad, wctx->vad_params,
                                          wctx->audio_buffer, wctx->audio_buffer_fill_size);
    if (n_segments > 0) {
        const float end_ms = whisper_vad_segments_get_segment_t1(segments, n_segments - 1) * 10.0;
        int end_pos = (int)(end_ms * WHISPER_SAMPLE_RATE / 1000);
        if (end_pos < wctx->audio_buffer_fill_size - av_rescale(wctx->vad_min_silence_duration, ...)) {
            av_log(..., "VAD detected %d segments, start: %.0f ms, end: %.0f ms\n", ...);
            run_transcription(ctx, frame, end_pos);   // ← 转录范围 = [0, end_pos]
        }
    }
}
```

**关键在最后一行**：`run_transcription(ctx, frame, end_pos)` ——
转录范围是 **buffer 的第 0 个样本到 `end_pos`**，而 `end_pos` 是"最后一段语音的结束"。

⇒ 若 buffer 内容是 `[静音 53s][语音 30s]`，VAD 找到语音段后，
**前面 53 秒静音原封不动被送进 whisper**。

官方文档（`doc/filters.texi`）的措辞也印证了这点：

> the filter will load an additional voice activity detection module that will be
> **used to fragment the audio queue**

是 **fragment**（分片），不是 **filter out**（滤除）。

### 3.3 纯静音实验（最干净的判据）

用 `anullsrc` 合成 30 秒**纯数字静音**（绝对无语音）：

| 配置 | 段数 | 首段文本 |
|---|---|---|
| 无 VAD | **11** | `请不吝点赞 订阅 转发 打赏支持明镜与点点栏目` |
| VAD @0.4 | **11** | **完全相同** |

**VAD 对纯静音的产出毫无影响。** 这是判决性证据。

### 3.4 阈值扫描（完整）

素材 `live_silence.wav`（140s，静音 34.0~87.7s）：

| 配置 | 段数 | 幻觉 | 耗时 |
|---|---|---|---|
| 无 VAD | 51 | **23（45%）** | **12.0s** |
| VAD @0.3 | 56 | 23 | 45.9s |
| VAD @0.4 | 56 | 23 | 48.2s |
| VAD @0.5 | 56 | 22 | 47.9s |
| VAD @0.5 + min_silence=2.0 | 51 | 23 | — |
| VAD @0.8 + min_silence=2.0 | 51 | 23 | — |

**阈值与 `vad_min_silence_duration` 只改变切分方式，不改变幻觉数量。**
而耗时在任何 VAD 配置下都是 4 倍左右。

> ⚠️ 注：官方建议 VAD 场景把 `queue` 提到 20（默认 3）。本次测的是默认值。
> 但按 3.2 的源码逻辑，`queue` 只影响 buffer 容量，
> **不改变"转录起点永远是 buffer 第 0 样本"这一事实**，故结论不受影响。

## 四、有效方案：三层防线

### 4.1 设计

```
① 静音预切除      silencedetect 扫出静音 → 取补集 → aselect 拼成连续音频 → 只喂语音给 whisper
② 重复文本剔除    同一句逐字重复 ≥3 次 → 全丢
③ 特征词剔除      感谢订阅 / 字幕制作 / 小铃铛 等模板文案
```

**① 为什么便宜**：`silencedetect` 扫 140s 音频仅 **0.2s**（2.5 小时约 5s），
比 VAD 的 whisper 推理便宜几个数量级。

**② 的关键约束**：**只对足够长的文本判重**。
短应答词（`好`、`啊`、`嗯`、`对`）重复出现是正常的，判重会误杀。
本实现取 `len(text) >= 8` 且 `重复次数 >= 3`。

### 4.2 逐层效果（同一素材，140s / 静音 53.6s）

| 层 | 处理 | 段数 | 幻觉 |
|---|---|---|---|
| 0 | 不做任何处理 | 51 | **23** |
| 1 | + 静音预切除 | 34 | **6** |
| 2 | + 重复文本剔除 | 29 | **1** |
| 3 | + 特征词剔除 | 28 | **0** |

第 2 层剔除的 5 段**全部是** `请不吝点赞 订阅 转发 打赏支持明镜与点点栏目`
（14.7s / 17.7s / 20.6s / 106.1s / 109.1s，映射后位置）。
真实讲话中，没人会把同一句话逐字重复 5 遍。

第 3 层剔除 1 段：`谢谢观看`（32.4s）。

### 4.3 时间轴映射

拼接改变了时间轴，必须映射回原轴。验证：

```
语音区间 [(0.0, 34.28), (87.42, 140.0)]
拼接后 35.3s  →  原 88.5s
计算：87.42 + (35.3 - 34.28) = 88.44  ✓
```

映射正确。**这一步不能漏**——漏了会让字幕与画面整体错位，且不报错。

### 4.4 落盘格式

终态输出 `final_segments.json`（已带原始时间轴时间戳）：

```json
[
  {"orig_start": 0.0,   "orig_end": 2.9,  "text": "都要講前面啊"},
  {"orig_start": 2.9,   "orig_end": 5.9,  "text": "我感觉我活生生要被"},
  ...
]
```

## 五、残余风险与边界

### 5.1 这不是万能药

| 场景 | 本方案是否覆盖 |
|---|---|
| 真静音（无任何声音） | ✅ silencedetect 抓到 |
| **有 BGM 但无人声** | ❌ **silencedetect 抓不到**（不是静音），`aselect` 不会切 |
| 低音量环境音（<-35dB 但非静音） | ⚠️ 取决于阈值设置 |
| 语音中间的短暂停顿（<1s） | ❌ 不切（也**不应该**切，会断词） |

**第二行是最大的盲区**：如果直播里长时间只有背景音乐（开场等待、中途放片），
这段会被判为"语音"送进 whisper，仍可能产生幻觉。

→ 本方案在"人声密集"的素材（如未明子）上接近完美，在"大量 BGM"的素材上会有残留。
**这是已知边界，v1 先这样，v2 再考虑引入真正的语音检测。**

### 5.2 判重可能误杀

若真实讲话中有人刻意重复同一句（如口号、教学重复），会被判重剔除。
缓解：阈值取 3 次且要求 ≥8 字。**仍需在真实使用中观察。**

### 5.3 特征词表必然不完整

当前表只能抓**见过的**幻觉模板。whisper 可能编出语法通顺、语义无关的普通句子，
这类一条都抓不到。

**判断**：真实幻觉率可能高于本报告测到的 0。要拿到可信数字，
需要人工标注"这段到底有没有人说话"——本报告没有做，也不声称做到了。

## 六、对实现的要求（阶段 2）

1. **`asr.py` 不启用 `vad_model`**（`enable_vad` 默认 False，且明确注释"实测无效"）。
2. **新增静音预切除流程**：
   - `speech_ranges(silences, total, pad=0.25)` → 语音区间
   - `extract_speech(wav, out, ranges)` → `aselect` 拼接（**空区间要特判**：
     实测空 `aselect=''` 表达式**不报错、直接输出原音频**，必须显式返回空结果）
   - `map_back(t, ranges)` → 时间轴映射
3. **三层过滤在全局做**，不在单分片内做（重复可能跨分片）。
4. **切点 padding 取 0.25s**：避免切断词边界，同时残留静音短到不足以诱发幻觉。
5. **映射函数必须与"字幕烧录"共用同一份实现** ——
   各写一份必然对不上（这是甲方案那次踩过的同类坑）。
