## 1. 摘要（Summary）

SliceQ 是一款基于 Qwen3.8-Omni-Flash 全模态大模型的 AI 直播切片 Windows 桌面应用。它服务于 B 站切片 man / 二创 UP 主，把"看完几小时直播录像、人肉找高光"这件数小时的苦役压缩到约十分钟：用户用自然语言描述想要的高光类型，AI 自动定位候选片段，一键完成切片、专业字幕（断句/校正/双语翻译）、转场、配乐、封面与标题文案，并可直接导出剪映 / Premiere / 达芬奇草稿进入精修。

一句话：**AI 负责找和粗剪，人负责审美和精修。**

> **v1.1 更新**：吸收 VideoCaptioner（GPL-3.0）验证过的字幕管线能力——免费 ASR 引擎、LLM 断句优化、字幕翻译、批量并发——以"借鉴重写 + 外部联动"方式集成，不复制其源码，SliceQ 保持 MIT 许可。
>
> **v1.2 更新（阶段 0 实测后）**：① 剪映草稿通道**已在真机验证通过**（详见 §7.4 假设表 A1）；② ASR 主引擎由"必剪私有接口"改为 **FFmpeg 内置 whisper 滤镜**（零新增依赖、零成本、零合规风险，已实测跑通）；③ 模型接入改为 SDK 直连（初版判断）；④ 成本线由 ≤¥2 收紧至 **≤¥1**；⑤ 明确"程序化触发剪映导出"不可行，导出由用户手动完成。
>
> **v1.3 更新（阶段 0.5 模型实测后）**：① **音轨理解能力已实测确认**——模型能逐字复述视频中的语音，娱乐/聊天类高光判定路径成立（A7）；② 模型接入修正为**双 transport**（官方 SDK 传本地路径 / 兼容端点传 base64），因实测发现**本地路径是 SDK 独有能力而非协议能力**（A2）；③ 实测出 **≈228 token/秒视频** 的成本规律，单条成本校准至 **≈¥0.45~0.55**（A8）；④ 中转站 base64 硬上限实测为 28,000,000 字符，副本压制策略按通道分档；⑤ 确立 `enable_thinking` 三态策略与空返回自检要求。

## 3. 背景（Background）

**痛点**：切片 man 的标准工作流是——录下/下载 2~6 小时直播录像 → 全程快进人眼找高光 → 剪映里手动切、打轴、加字幕 → 发布。找高光环节占去 70% 以上时间，且直播热度窗口只有 24 小时左右，慢一步流量就没了。

**为什么是现在**（四个条件同时成熟）：

1. **模型能力到位**：2026-09-18 发布的 Qwen3.8-Omni-Flash 原生理解文本/图像/音频/视频，1M 上下文；其 Agentic 长视频理解能自主决定"看哪段"，定位关键片段的 token 消耗比全量扫描低 45.7%（官方实测：44 分钟素材定位关键 6 秒仅耗 79,117 token）；可控 Caption 支持按需求输出带时间戳的结构化片段描述。
2. **成本断崖**：官方 API 每小时音频输入降价超 98%、音视频输入降价超 93%。**全模态同价**：输入 ¥0.8/百万 token、缓存命中 ¥0.1/百万 token、输出 ¥2.7/百万 token，不再区分文本/图像/音频/视频。
3. **剪辑执行层免费成熟**：FFmpeg 完成切片/字幕/转场/混音的全部执行工作，零授权费。
4. **转录成本可归零（阶段 0 实测确认）**：FFmpeg 9.0 的内置 `whisper` 滤镜（whisper.cpp 集成）可本地完成语音转录并直接输出 SRT/JSON，**零 API 成本、零新增依赖、零合规风险**，且原生支持 VAD 静音跳过——而 FFmpeg 本就是 SliceQ 必须分发的组件。这取代了原计划依赖的必剪/剪映私有接口方案。

**竞品空白**：剪映等工具只解决"剪"不解决"找"；海外 OpusClip 类 AI 切片产品订阅制收费、面向英文播客场景、不导出中文剪辑软件草稿；VideoCaptioner 长于字幕精加工但没有高光检测与剪辑能力。中文直播切片赛道没有"AI 找高光 + 专业字幕 + 草稿导出"的一站式工具。

## 4. 目标（Objective）

**目标**：让切片 man 的"找高光 + 粗剪"环节从 2~4 小时压缩到 10~15 分钟，且不锁定用户的精修工具链。

**关键结果（Key Results，验收时逐条核对）**：

| KR | 指标 | 目标值 |
|---|---|---|
| KR1 | 3 小时录像从导入到拿到候选清单的总时长 | ≤ 15 分钟（不含精修） |
| KR2 | 高光命中率：AI 给出的前 10 条候选中被用户采纳导出的比例 | ≥ 60% |
| KR3 | 单条 3 小时录像的模型 API 成本 | **≤ ¥1**（转录本地免费；仅精析与文案调用付费 API。阶段 0.5 实测校准 ≈**¥0.45~0.55**，余量约一倍） |
| KR4 | 免费开源发布，半年内 GitHub Star | ≥ 100 |

## 5. 目标人群（Market Segment）

**首要人群**：B 站切片 man / 二创 UP 主——给游戏、娱乐、虚拟主播做二创切片的个人创作者。他们的工作定义（JTBD）：*当我拿到一场直播的录像时，我要在热度窗口内快速找出值得发的高光并剪成能发的成片。*

**次要人群**：主播本人 / 直播间小运营（下播后快速出当日高光引流）。

**人群约束**：
- 使用 Windows 桌面，素材是本地大文件（几 GB 到十几 GB）或平台回放链接
- 对付费订阅敏感 → 本产品免费开源，模型 API 走 BYOK
- **BYOK 支持两种端点，视频传输方式不同**（阶段 0.5 实测）：
  - **阿里云百炼官方端点**（推荐，新用户 100 万 token 免费额度）→ 可传**本地文件路径**，副本体积宽松（≤100MB）
  - **OpenAI 兼容端点 / 中转站** → 只能 base64 内联或公网 URL，**副本须压至 ≤15MB**
  - 两者都**不需要上传到 OSS**。软件按 base_url 自动判定通道
- 精修习惯用剪映，部分用 PR / 达芬奇

## 6. 价值主张（Value Proposition）

| 维度 | 手动切片 | 剪映 | OpusClip 类 | VideoCaptioner | **SliceQ** |
|---|---|---|---|---|---|
| 找高光 | 人肉快进数小时 | 不支持 | 固定模板 | 不支持 | **自然语言自定义** |
| 粗剪出片 | 手动 | 手动 | 自动 | 不支持 | **全自动（切/字幕/转场/配乐/封面）** |
| 字幕管线 | 手动打轴 | 半自动 | 基础 | **专业（断句/翻译）** | **专业（断句/双语翻译）** |
| 精修衔接 | — | 本家 | 无（锁自家时间线） | 无 | **导出剪映/PR/达芬奇草稿** |
| 成本 | 免费但费时 | 免费 | 订阅制（$$） | 免费 | **免费开源 + BYOK 按量（约 ¥0.3~1.5/条）** |
| 中文直播适配 | — | 好 | 差（英文播客向） | 好 | **原生中文 + 直播场景** |

四条差异化护城河：
1. **需求用嘴说**："找出主播破防骂人的片段"和"找五杀操作"共用同一个输入框，不是预置标签。
2. **草稿导出三端**：AI 粗剪成果直接变成剪映/PR/达芬奇时间线，不绑架用户的精修工具。其中**剪映通道已真机验证通过**，且**（在字幕传递方案定论前）暂为唯一能携带可编辑字幕轨的通道**。
   > ⚠️ **待解决**：字幕跨软件传递目前是**未定问题**。达芬奇/PR 通道的字幕传递需选一条变通路径（Marker / 独立轨+片段名 / 烧录透明层），**阶段 4 立项**。在定论前，PR·达芬奇的定位是「**画面精修的兼容通道**」，字幕仍建议用户在剪映内完成或按附带的 SRT 手动重建。
3. **零订阅 + 近零边际成本**：软件免费开源；转录走本地 FFmpeg（零成本），单条成本约 ¥0.3~1.5，成本完全透明。
4. **专业字幕管线**：LLM 语义断句 + 校正 + 双语翻译，字幕质量对标字幕组水准，并打开"切片出海/外网搬运"场景。

## 7. 方案（Solution）

### 7.1 用户主流程（6 步）

```
① 新建任务 → 导入视频（拖入本地文件 / 粘贴回放 URL）
② 描述需求 → 自由提示词输入框（三个模板按钮：游戏 / 娱乐 / 通用，点击填入骨架可改）
③ AI 分析 → 两级流水线，进度条可见（转录中 → 粗筛中 → 精析中 n/m）
④ 候选清单 → 每条：起止时间 + 类型 + 评分 + 一句话描述
              点击条目即在内置播放器定位预览；起止点可拖动微调；勾选要的
⑤ 一键制作 → 切片 + 硬字幕 + 转场 + 配乐 + 封面 + 标题文案
⑥ 导出     → MP4 成片 / 剪映草稿 / PR·达芬奇 XML（三选一或全选）
        └ 剪映草稿：SliceQ 生成后，用户打开剪映手动导出成片（见 F12 说明）
```

**主界面布局**（给开发的线框约定）：

```
┌──────────────────────────────────────────────────┐
│ SliceQ   [新建任务]              [设置 API Key]  │
├──────────┬───────────────────────────────────────┤
│ 任务列表  │  候选高光清单（表格：时间/类型/评分/描述）│
│ ▸任务A    │ ┌─────────────────────────────────┐  │
│ ▸任务B    │ │ 内置预览播放器（点条目定位播放）    │  │
│          │ └─────────────────────────────────┘  │
│          │  [微调起止] [勾选] [一键制作] [导出]   │
└──────────┴───────────────────────────────────────┘
```

### 7.2 功能清单（按优先级）

**P0 — 核心闭环（v0.1 必须有）**：

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 视频导入 | 本地文件拖入（ffprobe 读取元信息）+ 粘贴 URL 经 yt-dlp 下载（B 站直播回放等，阶段 0 已实测可用） |
| F2 | 需求输入 | 自由提示词对话框 + 游戏/娱乐/通用三个模板按钮（点击填入可编辑骨架） |
| F3 | 两级分析流水线 | 粗筛（**本地转录**+低密度抽帧）→ 精析（候选段喂完整音视频），详见技术方案 |
| F3.5 | 本地 ASR 引擎 | 粗筛默认 **FFmpeg 内置 whisper 滤镜**（whisper.cpp，零依赖零成本，原生 VAD 跳静音）；faster-whisper 作为「高精度字幕」可选项（提供词级时间戳）；Qwen 音频理解兜底 |
| F4 | 候选清单 + 预览 | 时间戳/类型/评分/描述；内置播放器定位预览；起止点拖动微调；勾选 |
| F5 | 无损切片导出 MP4 | FFmpeg 按清单切片合成 |
| F6 | 专业硬字幕 | 转录文本 → **LLM 语义断句+校正** → SRT → 烧录进成片（白字黑边，样式可调） |
| F7 | API Key 配置 | BYOK：设置页填阿里云百炼 key，本地加密存储，用量与成本估算显示 |

**P1 — AI 全自动增强（v0.2）**：

| 编号 | 功能 | 说明 |
|---|---|---|
| F8 | 自动转场 | 片段间 FFmpeg xfade 0.5s 淡入淡出 |
| F9 | 自动配乐 | 内置免版税 BGM 库选择 + amix 混音 + 人声 ducking（说话时 BGM 自动压低） |
| F10 | 封面生成 | 抽高光帧 + 大字标题合成 1280×720 封面图 |
| F11 | 标题/简介文案 | 模型看完片段顺手生成 3 条候选标题 + 1 段简介，一键复制 |
| F12 | 剪映草稿导出 | 生成剪映可打开的草稿（片段+转场+字幕轨+标题轨已在时间线上排好）。**注意：切片由剪映草稿承载，成片渲染由用户在剪映界面手动导出**——剪映 7+ 已隐藏导出控件，程序化触发不可行（阶段 0 实测结论）。**剪映是三端中唯一能携带可编辑字幕轨的通道，故为草稿导出首选。** |
| F13 | PR / 达芬奇导出 | **达芬奇：直出 OTIO（`.otio`）**。**素材引用方式定为「甲方案」**（2026-09-25 决策）——OTIO **引用原始源视频** + `source_range` 承载切点，用户可在达芬奇里任意调整切点、重排片段。<br>**✅ 字幕传递已定论（不再是架构级问题）**：字幕走 **SRT 并行交付**。依据：① 达芬奇免费版原生支持 `File > Import > Subtitle` 按时间码精确插入（已查证）；② OTIO 0.18.1 无 `Text`/`Subtitle` 轨类型。<br>**⚠️ 甲方案连带要求：SRT 时间轴必须重映射** —— 成片是多段非连续高光的拼接，字幕时间戳须从"源视频绝对时间轴"换算到"新时间线时间轴"。**漏做不报错但字幕整体错位。**<br>**⚠️ `.otio` 不自动链接媒体** —— 官方定义如此（`.otio` 只含元数据）。用户导入时会遇「找不到片段」弹窗。导出包**必须附 `导入说明.txt`** 写明应对方式。<br>**⚠️ 不含"一键推送到达芬奇"** —— 脚本直连经实测不可行（`fusionscript.dll` 于 `DllMain` 触发不可捕获的 `0xC0000005`），已永久弃用。用户需手动导入。<br>**⚠️ FCP7 XML 通道实测无法被达芬奇导入**，仅保留为老工具兼容选项。PR 通道待实测是否支持 OTIO。**`.otioz` 不采用**（甲方案引用原片，打包体积不可接受）。 |
| F14 | 字幕翻译 | 免费通道（必应/谷歌）+ LLM 精翻（反思式）；输出双语 SRT 与双语烧录成片，打开出海/搬运场景 |
| F15 | 批量并发处理 | 多录像任务队列，粗筛/精析并发执行（API 限流友好的并发度控制） |
| F16 | VideoCaptioner 联动 | 检测本机已安装的 VideoCaptioner（**注意：官方为安装包发行，非 pip 包、无 PATH CLI**，检测方式需按其安装形态设计），以独立进程调用实现 GPL 合规隔离；未安装则引导用户自行安装。**本功能的具体联动方式待阶段 2 前重新论证** |

**P2 — 后续版本（不在本次开发范围）**：竖屏 9:16 自动重构（横转竖+人物跟踪）、B 站弹幕 XML 导入作为高光信号、实时直播流切片（Qwen3.8-Omni-Flash-Realtime）、提示词策略社区分享。

### 7.3 技术

见同目录《TECH-DESIGN.md》。技术栈：Python 3.13 + PySide6 + FFmpeg（含内置 whisper 滤镜）+ **DashScope 官方 SDK** + yt-dlp + OpenTimelineIO + otio-fcp-adapter + pyJianYingDraft，PyInstaller 打包单 exe。

> ⚠️ 不是 OpenAI 兼容模式。阶段 0 实测确认：OpenAI 兼容端点只接受公网 URL，无法传本地视频；DashScope 官方 SDK 对 7~100MB 视频支持**本地路径直传**，这是精析级能把本地候选片段送进模型的前提。
