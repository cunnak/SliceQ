# SliceQ v0.1.1

> 修 v0.1.0 里一个会让分析**永久卡住**的缺陷。**建议所有 v0.1.0 用户升级。**
> 详细取证过程见 [`reports/V0.1.1-HOTFIX-REPORT.md`](../reports/V0.1.1-HOTFIX-REPORT.md)。

---

## 修了什么

### 🔴 严重：点「开始精析」后卡在「准备中…」不动

**现象**：选好视频开始分析，进度条一直是 0、标签一直「准备中…」，
任务状态停在「转录中」，但**实际什么都没在跑**（进程活着、CPU 0%、不报错）。

**根因有三个，叠在一起**：

1. **子进程管道死锁（真卡死）**
   调用 ffmpeg 扫静音时，代码开了管道却**不读取**。ffmpeg 把缓冲区
   （Windows 约 64KB）写满后就永久阻塞，而程序在等它退出 —— 互相等。
   实测：84 分钟音频的那条命令，单独跑 **0.8 秒**就结束，
   却往 stderr 写了 **95,662 字节** > 64KB ⇒ 必然死锁。
   这也是为什么**只有部分素材会中招**：静音段越多越容易触发。

2. **进度显示断线**
   手动单条分析时漏传了一个开关，导致**进度回调根本没接上** ——
   所以即使没卡死，进度也永远不动。

3. **中断后状态变成谎话**
   程序被强杀/卡死后结束，任务状态永远停在「转录中」。
   现在启动时会自动检查并回退到有数据支撑的状态（已导入 / 待导出）。

### 另外

- 启动时会清理上次被中断留下的「进行中」状态，并在日志里说明改了什么

## 你的老任务怎么办

**不需要手动处理。** 装好新版后直接打开，那条卡住的任务会：
- 状态从「转录中」自动变成「已导入」
- 直接点「重新分析」即可 —— 已经做完的步骤（音频提取等）会被复用，不会白跑

> ⚠️ 转录这一步在 CPU 上跑 84 分钟素材**需要几十分钟**（约 0.9× 实时）。
> 这次进度条会真的走，你能看到它到哪一步了。

## 升级方式

1. 下载新的 `SliceQ.exe`，**覆盖** `%LOCALAPPDATA%\Programs\SliceQ\SliceQ.exe`
   （桌面快捷方式不用改）
2. 或者只把下载的 exe 放到任意位置直接双击 —— 你的配置、API Key、模型都在
   `%APPDATA%\SliceQ\`，**与 exe 放在哪无关**，不会丢。
