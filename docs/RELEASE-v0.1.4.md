# SliceQ v0.1.4 — 运行时不再闪出终端窗口

## 修了什么

SliceQ 运行时会**时不时闪出一个终端窗口**。这版把它彻底消掉了。

**根因**：SliceQ 是 GUI 程序（没有控制台），而 ffmpeg / ffprobe 是**控制台程序**。
Windows 在"没有控制台的父进程 + 控制台子进程"这种组合下，会**为子进程新建一个
控制台宿主窗口** —— 就是屏幕上闪的那一下。

**关键点：重定向输出并不能避免它。** 项目原本 19 处调用全都已经重定向了
（`capture_output=True`），照样会弹。必须显式声明 `CREATE_NO_WINDOW`。

实测对照（同一个 exe，同一套检测）：

| 版本 | 启动一次的控制台窗口事件 |
|---|---|
| v0.1.3 | **6 个** |
| v0.1.4 | **0 个** |

---

## 怎么改的

新增 `sliceq/subproc.py` 作为**所有子进程的唯一入口**，默认注入
`CREATE_NO_WINDOW`；19 处调用点（12 个文件）全部改走它。

**为什么不逐处加参数**：这个项目已经两次栽在"在 N 处修了、漏了第 N+1 处"
（子进程管道排空、进度回调接线），所以这次改成唯一入口 +
一个**静态检查自测**（`selftest_subproc_flags.py`）—— 以后谁新写调用点漏了，
测试会当场失败，而不是等你来报。

---

## 对使用有影响吗

**没有。**

- 子进程的输出、退出码、超时行为**逐字节一致**（5 个用例实测，含 3MB 的 JSONL、
  200KB 的 stderr、中文、ffprobe JSON）
- 无数据/schema 变更，配置与历史任务不受影响

---

## 顺带修掉的一个潜在崩溃

改造过程中发现 `asr.py` / `editor.py` 里有个**命名撞车**：
局部变量 `proc` 与模块名冲突，会让转录路径抛
`UnboundLocalError`。这版把模块改名为 `subproc` 从根上消除。
（该问题由本版的端到端验证抓出——静态检查与 GUI 自测都发现不了。）
