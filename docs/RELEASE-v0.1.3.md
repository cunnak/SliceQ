# SliceQ v0.1.3

**建议所有用户升级。** 这个版本修掉一个"看不见的时间代价"：
**换一版筛选结果，原本要重付整条素材的转录时间**（84 分钟素材约 40 分钟）。

---

## 🔴 「重新分析」不再重跑转录

### 问题

转录是**本地免费但最慢**的一步（84 分钟素材约 40 分钟）。
而它与你调整的"筛选强度""需求描述"**完全无关** —— 转录只是把语音变成文字，
换一版候选根本不该重做它。

但原先两条路都会重付：

| # | 位置 | 问题 |
|---|---|---|
| ① | `asr.transcribe_chunk()` | 每次进来都 `dest.unlink()` 把已有的识别结果删掉再重跑 —— **转录结果从来就不是缓存** |
| ② | 「重新分析」按钮 | 调 `clear_cache()` → `rmtree(work/)`，连 `audio.wav` 和 `chunk_*.speech.wav` 一起删 |

所以"我就想换个筛选强度再看看"的代价是 40 分钟，而界面上完全看不出来会这样。

### 修法

**① 转录分片现在是真正的缓存**，并带**参数指纹**：

- 指纹 = 模型文件（名 + 大小 + 修改时间）+ 语言 + 是否用 GPU
- 指纹一致 → 直接复用识别结果，**一秒都不用等**
- 指纹变了（你换了模型档位）→ 自动重跑，不会拿旧结果糊弄
- 升级前留下的旧缓存（没有指纹文件）→ 仍按可用处理
  （否则升级后第一次重跑反而更慢，与本次修复的初衷相反）

**② 「重新分析」默认保留转录**，只清"候选 / 精析"的产物：

```
保留  audio.wav、chunk_*.wav、chunk_*.speech.wav、chunk_*.speech.jsonl（+指纹）
清掉  screen.jsonl（粗筛缓存）、refine/（精析副本）、frames/（抽帧）
```

> 需要强制重塑的场合（例如换了识别模型、或怀疑转录本身有问题）：
> `pipeline.clear_cache(video, keep_transcript=False)` 仍会清空整个工作目录。

## 另外

- **修了一处"日志自己打自己脸"**：粗筛在**全部窗口都命中缓存**时会打印
  「粗筛完成，候选 0 段」，而紧接着流水线上层打印「找到 6 个候选段」
  （缓存候选由上层补回）。现在会写明"本轮新增候选 N 段（M 个窗口复用缓存）"。
- 数据库 schema 仍是 **v6**（无新增迁移）。

## 验证

新增自测 `selftest_asr_chunk_cache.py`（**13 项**）：

| 守什么 | 判据 |
|---|---|
| 缓存命中时**完全不碰音频** | 传一个**不存在的音频路径** —— 走缓存就不会调用 ffmpeg，能正常返回 |
| 参数变了必须重跑 | 改语言 / 改 GPU 开关后，必须真的去跑（同上，会因音频不存在而失败） |
| 模型换了 ⇒ 指纹变 | 同一个文件写不同长度，指纹必须不同 |
| 老缓存仍可用 | 删掉指纹文件后仍能复用（升级不倒退） |
| `clear_cache` 的两种模式 | 默认保留转录 5 个文件、清掉 `screen.jsonl`/`refine`/`frames`；显式全清时清空 |

★ 第一条判据值得一提：**"传一个不存在的音频"** 能干净地区分
"走了缓存"与"没走缓存"——比统计调用次数更简单，也不依赖 mock。

## 升级方式

单文件直接替换。配置、API Key、模型缓存、历史导出都在 `%APPDATA%\SliceQ\`，
与 exe 位置无关，升级不丢。

**已有的转录缓存**（`%APPDATA%\SliceQ\work\<素材名>\chunk_*.speech.jsonl`）
在升级后**继续有效** —— 下次「重新分析」会直接复用它们。
